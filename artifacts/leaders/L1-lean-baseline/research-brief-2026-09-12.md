## B.1 What changed in the mathematical picture

**A1 is no longer "a restatement that has not been done".** The D12 ledger's closure rule for
A1 is explicit: *"the blocker stays open until upstream restatement"* of the three promoted
theorems whose hypothesis `1 < c` is overstrong. That restatement now exists, compiles and is
re-audited, on a byte-copy of the release:

- `Poincare.Longrun.Evolution.gibbsTerm_strictAnti : ∀ c, 1 ≤ c → StrictAnti (gibbsTerm c)`
- `Poincare.Longrun.Evolution.gibbsTerm_step_lt : 1 ≤ c → 0 < u → gibbsTerm c (x+u) < gibbsTerm c x`
- `Poincare.Longrun.Evolution.perelmanF_step_lt : (∀ i, 1 ≤ c i) → …`

The `c = 1` case is the real content: `deriv (gibbsTerm 1) x = -((x-1)²) e^{-x}` vanishes at the
isolated flat spot `x = 1`, so the proof glues `StrictAntiOn (gibbsTerm 1) (Iic 1)` and
`(Ici 1)`; for `1 < c` the original proof is reused. The `perelmanF` step is the existing
`Finset.sum_lt_sum` argument with the strict component from the sharp one-variable step. All
conclusions are unchanged and the hypotheses are weakened, so this is a strengthening — no
theorem was replaced by a weaker one, and no new hypothesis was introduced.

**Sharp-only consumer.** `perelmanF_step_lt_at_threshold_one` instantiates the restated theorem
at `c ≡ 1`. That application cannot be typed against the old statement (it would need
`1 < 1`), so it is direct evidence that the restatement is doing work rather than being a
renaming.

**P5 is no longer a manual re-run.** `p5_hash_gate.py` is a fail-closed, executable gate over
