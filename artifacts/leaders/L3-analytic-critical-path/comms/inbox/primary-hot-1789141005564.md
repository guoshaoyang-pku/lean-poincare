# Hot dispatch instruction

At the next checkpoint, create at least two real child-task JSON files in comms/outbox/. Use unique IDs prefixed L3-child-. Each JSON must contain id, group_id, parent_node, deps, lane, acceptance, host_pool, requires_lean, max_hours, and a concrete objective tied to an existing blocker or frontier. Do not create placeholders or duplicate queue tasks. Keep each child in its own worktree and classify expected evidence. Then update checkpoint.json with the child IDs, timestamp, and blocker status. The dispatcher will import only schema-valid files.
